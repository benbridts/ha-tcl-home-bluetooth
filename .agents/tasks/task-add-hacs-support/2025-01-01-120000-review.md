# HACS support and installation documentation

This change adds the files needed to list the integration in HACS (Home Assistant Community Store) and provides user-facing documentation. A `hacs.json` configuration file is added at the repository root, `manifest.json` gets a codeowner and a name update from "TCL Soundbar" to "TCL Home Soundbar", and a new `README.md` covers both HACS and manual installation paths.

Watch for: The integration name "TCL Home Soundbar" is specific enough to suggest a single-product scope; the user has indicated the name should be generic enough to cover any TCL soundbar that works with the TCL Home app via Bluetooth (possible).

## High-level view

The naming choice "TCL Home Soundbar" appears in three places (hacs.json, manifest.json, README.md) and currently reads as a single-device brand rather than a family-encompassing label. The user's steering message requests something broad enough to cover any TCL soundbar supported by the TCL Home app over Bluetooth. Whether the current name achieves that depends on interpretation — "TCL Home Soundbar" could read as "the soundbar product called TCL Home" or as "TCL soundbars manageable via the Home app." A name like "TCL Home Bluetooth Soundbars" or simply keeping the repo name phrasing ("TCL Home Bluetooth") might communicate the family scope more clearly.

## Naming scope vs. user intent

The name "TCL Home Soundbar" shows up in `hacs.json`, `manifest.json`, and throughout the README. The user's steering message explicitly asks for a name generic enough to cover any TCL soundbar that uses the TCL Home app via Bluetooth. The current singular "Soundbar" could be read either way — a category name (like "TCL Home Soundbar" meaning "TCL Home's soundbar integration") or a singular product name. Given the README's "Supported Devices" section already lists one specific model and invites others, the intent is clearly multi-device, but the name doesn't make that immediately obvious to someone browsing HACS.

Options that might better signal the family scope:

- "TCL Home Soundbars" (plural, minimal change)
- "TCL Home Bluetooth" (matches the repo name, broadest)
- Leave as-is and rely on the description text to clarify

This is a subjective naming call, not a blocking issue. The integration will function identically regardless. Notably, the BLE matcher in manifest.json already uses `local_name: "TCL*"` — the broad wildcard pattern aligns with the multi-device intent even though the display name is singular.
